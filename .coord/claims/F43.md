- **Design (fixed for the implementer):**
  - Match: case-insensitive substring against `id + " " + title`.
  - `/` engages filter-edit only in specs view when no editor/naming overlay
    is active; while engaged, printable chars append, Backspace edits,
    selection re-anchors to top on every edit (F42 precedent).
  - Esc: clears the keyword and exits filter mode (filter empty + not
    engaged → Esc keeps its existing detail-pane behavior).
  - Enter: exits filter-edit mode but KEEPS the keyword, so `↑`/`↓` browse
    the narrowed list; `/` re-engages; editing the text again re-anchors.
  - Switching projects resets filter + selection (extends the existing
    `switching_project_resets_selection_and_scroll` behavior).

## Change summary

- `crates/tui/src/app.rs`: new `App::filtering`/`App::filter` (separate from
  the F42 editor-picker filter) and `App::visible_decisions()` — the single
  source of truth for the narrowed list, used by both `update()` (selection
  clamp/re-anchor) and views.rs (rendering). `/` engages in specs mode only
  when no overlay is active; while engaged, chars append (e/p/q type into
  the query), Backspace edits, both re-anchor selection to the first match;
  Enter disengages keeping the keyword; Esc clears the keyword and
  disengages; a kept keyword is also cleared by Esc (specs mode); plain Esc
  with an empty filter keeps its old detail-pane behavior. Left/Right/Tab
  share `reset_view_state`, which now also clears the filter (filter state
  can never leak across projects or views); Up/Down clamp against the
  visible count.
- `crates/tui/src/views.rs`: `render_specs` splits a one-line filter row
  (`filter: <query>   <matches>/<total>`, cyan) above the list whenever
  filtering or a keyword is kept — byte-identical layout otherwise; rows and
  the detail pane follow `visible_decisions()`.
- Spec: TUI-008 (2 requirements, 5 scenarios) appended to specs/060-tui.spec.
- Glue: +5 scenario fns / +6 delegate calls; docstring count 257 → 263.
- Docs: README TUI paragraph, docs/TUI.md key table + §3 walkthrough, USAGE
  §9 specs bullet.
- Deviation accepted: Tab also resets the filter (shares the existing
  view-reset seam); sub-agent pinned it with an extra test
  (`tui_tab_resets_decision_filter_with_the_rest_of_the_view`, hosted under
  the project-switch scenario's glue).
