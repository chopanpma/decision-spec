## Task summary

Pilot evidence (tvgo, 2026-10-02), two defects in the import-linter path:

(a) **Scope.** The generated `.importlinter` emitted a forbidden+layers contract
pair for **every** rel, including rels touching the three frontend containers.
import-linter is python-only: `frontend_app` / `frontend_components` /
`frontend_lib` are not importable modules, so the generated config cannot run
as-is — `lint-imports` would fail to resolve them. Contracts must be scoped to
rels where **both** endpoints have a `[stack.fitness.packages]` mapping; the rest
become an actionable TODO naming the container and the key to add.
This replaces the old "fall back to the bare container id" behavior (which is
what made the file un-runnable).

(b) **No `root_package`.** With no `root_package` configured the file is
un-runnable (verified on tvgo: the fitness adapter flips to `FAILED` on the
`'root_package'` key). **Keep that TODO behavior** — it is honest, and an empty
`root_package =` line would make import-linter reject the file outright.

Also pinned by this task: the import-linter rule direction is **already
correct** (forbidden source = the rel's TO side, forbidden module = FROM side;
layers allow FROM → TO). The inversion is depcruise-only (F9). This claim adds a
direction assertion for import-linter so it cannot regress silently.

### NEW FINDING (not in the board text): contracts were never evaluated

The generated file spelled contract sections `[contract:<id>]`. import-linter's
INI reader (`IniFileUserOptionReader._build_from_config`, 2.5.2) only accepts
sections starting with `importlinter:` — everything else is silently dropped, so
the file always printed `Contracts: 0 kept, 0 broken.` and **exited 0**. The
fitness row therefore reported a pass while checking nothing. Sections are now
`[importlinter:contract:<id>]` (same ids, so contract identity is unchanged).
