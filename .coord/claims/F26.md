## Design

- `parse::lint` returns the same `Diagnostic { file, line, message }` shape
  as `validate`; rules (lexical, per the guide):
  1. decision context missing/empty;
  2. consequences missing/empty, or containing no minus entry
     (`" - "` or leading `"- "` — "a decision with no minus is not finished");
  3. requirement text not EARS: must contain a WHEN/IF/WHILE trigger token
     AND a SHALL token (token-split, so SHIFT does not count as IF);
  4. scenario id not snake_case (`^[a-z][a-z0-9]*(_[a-z0-9]+)*$`);
  5. scenario defined in a spec but listed by no requirement (orphan —
     generates no gate row, so nothing pins it).
- **Status legality is NOT re-implemented**: `validate` already enforces
  superseded↔superseded_by presence, target existence, and enum values
  (board's "legal status transitions" item). The lint stays opt-in (`--strict`);
  plain `check` behavior is unchanged (existing `cmd_check(&root)` call sites
  become `cmd_check(&root, false)` — characterization that nothing shifts).
- Repo audit before writing code: all 52 requirements carry SHALL +
  WHEN/IF/WHILE, all 38 consequences carry minuses, all scenario ids are
  snake_case, no orphan scenarios — so `check --strict` must pass on this
  repo itself (rule 5's own bar).
