# Claim F19 — escape parentheses in Mermaid flowchart edge labels

- **Owner:** main-orchestrator (execution delegated to coder agent-1)
- **Status:** claimed
- **Started:** 2026-10-01

## Task

Bug (user-reported, reproduced 2026-10-01 against current Mermaid via
mermaid.ink): `mermaid_model` writes rel labels raw into `-->|label|`, and a
label containing `(…)` makes the whole diagram a Mermaid syntax error
(verified: same diagram without parens renders 200; with parens 400; node
labels with parens inside quoted `["…"]` are fine; PlantUML unaffected;
sequence-diagram message text with parens is fine).

## Scope

- crates: codegen (the `mermaid_model` edge-label rendering only)
- root: README.md only if the codegen mapping table needs a note (it does
  not — no behavior-doc change), Cargo.lock (auto)
- OUT of scope: plantuml (unaffected), `mermaid_flow` sequence labels
  (parens verified fine), DSL strings (parens stay legal in .spec)

## Fix

Add a small label sanitizer used for Mermaid flowchart edge labels only:
`(` → `&#40;`, `)` → `&#41;` (verified rendering 200), and `|` → `/`
(a raw `|` would terminate the label early — same class of bug, prevent it
while here). Node labels keep the existing quoted rendering (parens already
safe there). Escape happens at render time; the IR keeps the raw strings.

## Test plan (red first)

1. `mermaid_model` with a rel label containing `(api, application)` →
   emitted `.mmd` contains `&#40;api&#41;`, and no raw parens in the edge
   label position.
2. Rel label containing `a | b` → rendered label contains `a / b`.
3. Existing diagram tests (nested alts, model shapes) stay green; plantuml
   output for the same workspace keeps raw parens.
