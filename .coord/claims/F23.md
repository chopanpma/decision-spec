# Claim F23 — edge labels: plain characters only (GitHub decodes entities)

- **Owner:** main-orchestrator (execution delegated to coder agent-1)
- **Status:** review
- **Started:** 2026-10-02 (no claim file existed at task start; created by
  the executor with the standard shape + evidence)

## Task

F19 regression (user-reported on the tvgo draft PR, error showed decoded
parens): F19 escaped edge-label parens as `&#40;`/`&#41;`, verified 200 on
mermaid.ink — but GitHub's markdown pipeline HTML-decodes entities before
Mermaid parses the fence, so Mermaid receives a literal `(` and fails with a
parenthesis parse error. Fix: emit plain characters only; keep `|` → `/`.

## Scope

- crates: codegen (`mermaid_edge_label` + its tests only)
- root: none (README documents no escaping — verified by orchestrator)
- OUT of scope: node labels (quoted `id["…"]` accepts parens — GitHub's
  error was only the edge-label line), plantuml, `mermaid_flow`

## Change summary

- `crates/codegen/src/lib.rs`:
  - `mermaid_edge_label` rewritten: `(`/`)` dropped (orchestrator's
    suggestion — "queries (api, application)" reads fine as
    "queries api, application"), `|` → `/` kept (terminates the label in
    every Mermaid version), and every other character outside
    `[A-Za-z0-9 ,./:-]` collapses to `-` (so `&`/`#`/entities can never
    survive into the label — this is what makes the GitHub decode attack
    impossible rather than merely moved). Doc comment now records both
    facts: mermaid.ink accepts entities but GitHub decodes them pre-parse.
  - Tests: `mermaid_edge_labels_escape_parens` →
    `mermaid_edge_labels_drop_parens` (intended semantic change, pinned);
    new `mermaid_edge_labels_are_plain_ascii_only` asserts an edge label
    built from `queries (v2) & cache #40 — utf8 ✓` contains no `(`, `)`,
    `&`, or `#` and collapses out-of-charset chars to `-`;
    pipe/plantuml tests unchanged.

## Judgment calls

1. **Substitution choice**: parens dropped (orchestrator's explicit
   suggestion); all other out-of-charset characters map to `-` rather than
   being dropped, so "R&D" reads "R-D" instead of "RD" and word boundaries
   stay visible.
2. **Charset scrub vs targeted fixes**: scrubbing the whole edge-label
   charset (not just parens/pipe) is the conservative reading of the brief's
   "smallest conservative label charset" and makes the whole class
   (entities, `&`, unicode punctuation) impossible instead of patching one
   character at a time per renderer.
