# Claim F50 — `decispec tui` opens on the current project only

- Owner: kimi-agent
- Claimed: 2026-10-26
- Status: claimed

## Task

User request: "modify the tui so it only opens with the project you are in,
instead of having all projects registered". Running `decispec tui` inside a
project must open the cockpit scoped to that project alone (no registry load,
no seeding, no project switcher over foreign projects). Registry mode stays
only as the fallback when cwd is not inside a project, plus an explicit
`--all` escape hatch.

## Scope

In scope:

- crates/cli/src/main.rs (`cmd_tui` selection seam + `--all` flag + tests;
  `find_project_root` cwd-parameterized variant if needed)
- Root: specs/060-tui.spec (startup scenarios), README.md, docs/USAGE.md,
  docs/TUI.md, .coord files

Must NOT touch: crates/tui (App already handles a single project), gate,
codegen, registry format.

## Test plan (red first)

cli tests (cwd passed explicitly — no process-cwd games):

1. `tui_opens_current_project_only_when_inside_one` — cwd inside a project
   (incl. a nested subdir) → entries = exactly that project, and the registry
   file is NOT created (no seeding side effect).
2. `tui_falls_back_to_registry_outside_a_project` — cwd in a bare dir →
   registry entries (pre-written registry, no seeding needed).
3. `tui_all_flag_keeps_registry_mode_inside_a_project` — cwd inside a
   project + all=true → registry entries, not the single project.

Red = new fn/flag compile-red (documented F47/F48 precedent); behavioral pins
are the entry-list assertions + the no-seeding side-effect assertion.

## Design notes

- New seam `tui_project_entries(cwd, all, reg_path, seeds) -> CliResult<Vec<ProjectEntry>>`:
  !all && find_project_root(cwd) ok → vec![entry_for_root(root)] (canonical
  path, name from [project], no registry write); else load_or_seed_registry.
  `entry_for_root` = register_project minus the registry upsert.
- `--register <DIR>` unchanged; `--all` new; both composable.
- Exit-code contract unchanged.

## Change summary

- `cli`: `cmd_tui(register, all)`; new seam `tui_project_entries(cwd, all,
  reg_path, seeds)` — !all && cwd inside a project → exactly that project
  (canonical path, name from [project]); the registry file is not read, so
  single-project startup has no seeding side effect. Otherwise (cwd outside
  any project, or --all) → load_or_seed_registry as before. `entry_for_root`
  extracted from register_project (register path unchanged). New
  `find_project_root_from(start)`; `find_project_root()` delegates.
