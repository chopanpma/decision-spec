# Claim F36 — In-TUI new spec file creation (name → skeleton → editor)

- **Task summary:** `e` in the cockpit currently only opens **existing**
  spec files (picker over `sources`; zero files → a status message). F36
  adds creation: `n` in the picker (or `e` on a project with no spec files)
  opens a name prompt; a valid name opens the editor on a parseable
  starter skeleton (placeholder `PREFIX-001` decision + spec, dirty so
  `Ctrl+S` writes it). The file lands on disk **only** through the existing
  explicit save — no new write path. `cli::save_spec_file` is hardened:
  refuse absolute / `..` / non-`specs/` first-component paths, create
  parent dirs (so `payments/010.spec` works).
- **Agent:** main-orchestrator (opencode), 2026-10-20.
- **Files in scope (exact):**
  - `crates/tui/src/app.rs` (Editor fields naming/name; open_picker;
    update_editor naming branch; validate_new_name; app tests)
  - `crates/tui/src/editor.rs` (skeleton_for + test)
  - `crates/tui/src/views.rs` (picker title hint; naming prompt render)
  - `crates/cli/src/main.rs` (save_spec_file hardening + cli tests)
  - `specs/060-tui.spec` (new decision TUI-006 + scenarios)
  - `specs/040-commands.spec` (CMD-008 new requirement R5 + scenarios)
  - `tests/glue/__init__.py` (pins for the new tests)
  - `tests/generated/**`, `docs/decisions.md` (regenerated)
  - `README.md`, `docs/USAGE.md`, `docs/TUI.md` (creation documented)
  - `.coord/BOARD.md` (F36 row only), this claim file
- **Must not touch:** other crates, `Cargo.toml`/`Cargo.lock`, other spec
  files, other docs, `.coord/` files other than this claim. Note: F35 is
  `review` and owns pointer lines in README/USAGE/TUI.md — F36's doc edits
  are disjoint sections (TUI keys/§5 editing), flagged here per §2.
- **Test plan (red-first):**
  1. tui app tests: `e` with zero sources opens naming directly; picker `n`
     opens naming, `esc` returns to picker; naming `Enter` with a valid
     name opens a dirty editor on `specs/<name>` with the skeleton and
     empty diagnostics; invalid names (empty, no `.spec`, `..`, absolute,
     collision with an existing file) are refused with a status message and
     stay in naming; `esc` in naming with no files closes the editor.
  2. tui editor test: `skeleton_for` text passes `validate_edit` clean (so
     the new editor opens with zero diagnostics).
  3. cli tests: `save_spec_file` creates a new file including missing
     parent dirs; refuses `../…`, absolute, and `specs/../…` paths with an
     error naming the refusal (RED today: bare `root.join` write, no
     confinement).
  4. Full loop: `cargo build && cargo test`, `decispec check`, `gen`,
     `gate` — new scenarios pinned via glue (F34 invariant), gate green.
  5. Docs updated; negative pin proof only if the gate self-check flags a
     mismatch (it is the standing audit).
- **Status:** landed 2026-10-20. Red-first confirmed (new tests fail to

## Change summary

- **TUI** (`crates/tui`): `Editor` gains `naming` + `name`; `e` with zero
  spec files opens the name prompt directly; `n` in the picker switches to
  it, `esc` returns to the picker (or closes when there is none).
  `validate_new_name` (pure): relative to `specs/`, must end `.spec`, no
  `..`/absolute, leading `specs/` stripped, collision refused with a
  status message. `skeleton_for` (editor.rs, pure): minimal PREFIX-001
  decision+spec that passes `validate_edit` clean against siblings and an
  empty workspace; the opened buffer is dirty so `Ctrl+S` writes it
  through the existing `SaveSpec` seam (no new write path). views.rs:
  picker title advertises `(n = new)`; naming prompt rendered with cursor.
- **cli** (`crates/cli/src/main.rs`): `save_spec_file` hardened — refuses
  absolute paths, `..` components, and non-`specs/` first components
  ("refusing to write outside specs/"); creates missing parent dirs so
  nested names (`payments/010.spec`) save. (Pre-change the function was a
  bare `root.join` write — the red test proved an escape write succeeded.)
- **Specs/glue:** new decision TUI-006 (6 scenarios) in 060-tui.spec;
  CMD-008 gains R5 (2 scenarios) in 040-commands.spec; 8 glue pins; glue
  docstring count 204 → 212.
- **Docs:** README TUI table row, USAGE §9 (editing + keys), docs/TUI.md §5
  (edit-or-create walkthrough).
- **Evidence:** red-first (tui: missing-field compile errors; cli: ENOENT
  on parent dirs + escape write proving the hole) → `cargo test` **212
  passed / 0 failed** (204 + 8), clippy clean → `decispec check` exit 0
  (38 decisions / 52 requirements / **213 scenarios**) → `gen` clean →
  `gate` **PASS 213 rows** with the 8 new rows RAN (pytest adapter) and
  the F34 pin self-check green (exact bijection). Release rebuilt so the
  `~/.local/bin` symlink serves the new sub-behavior.
- **Not done / non-goals:** no file deletion/rename from the TUI; the
  skeleton's PREFIX ids are the author's to rename (check enforces
  consistency, as designed); no completion/autocomplete in the name
  prompt.
