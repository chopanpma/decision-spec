  current project, edit it in a text pane with **live `file:line` diagnostics**

  `parse::parse_file`/`merge`/`validate` over the project's sources — the

## Change summary

- **tui:** `editor.rs` — `EditorState` (char-safe line editor: insert/newline/
  backspace/delete, arrows/home/end/page, scroll-to-cursor, dirty flag) +
  `validate_edit` (edited text swapped into the project's sources, whole
  workspace re-parsed + validated; parse errors phase-first, sibling-file
  errors surfaced). `app.rs` — `Input` extended (Home/End/PageUp/PageDown/
  Backspace/Delete/Ctrl(char)); `Action` gains `SaveSpec{file,text}` +
  `CreatePr` (Clone, no longer Copy); `Editor` session (picker/editing,
  confirm-discard); `ProjectData` carries `sources` and `error()` keeps them
  so broken projects are editable; `mark_saved`. `views.rs` — picker list,
  editor pane with dirty marker + live diagnostics pane + real cursor.
- **cli:** `translate_event` extended (control-modifier chars, editor keys);
  `read_spec_sources`; save handler (`save_spec_file`: write → whole-
  workspace check → status report, broken-save reported not hidden);
  `refresh_project` in-place reload; PR flow (`pr_readiness` with injected
  `gh_ok` for testability, `pr_branch_name` UTC timestamp via Hinnant civil
  conversion — the +719468 shift caught by test, `create_spec_pr`:
  branch → stage `specs/` only → refuse non-spec changes → commit → push →
  `gh pr create --draft --base main`, never merges); `TerminalGuard` Drop
  restores raw mode + alt screen when setup fails midway (F31 review nit).
- **Exit-code surface:** unchanged — `tui` stays 0/2; save/PR failures are
  status-bar messages, never process exit codes.
- **Root docs:** README `tui` row rewritten (editor + draft PR), USAGE §9
  gains "Editing and PRs". `docs/decisions.md` regenerated (`decispec index`).
- **Not done (out of scope):** running gates/adapters from the TUI (still
  the deferred explicit decision); structural/spec-growth work belongs to
  F33's claim (parallel) — F32's new tests were pinned there.

## Review round 1 (2026-10-20): REQUEST-CHANGES → fixed

Reviewer: `.coord/reviews/F32.md`. Production behavior was verified correct;
both majors were test-level. Fixes:

1. **Major (specs-only staging blind + refusal untested):** the PR happy-path
   fixture now also dirties a non-spec `notes.txt`, which makes an accidental
   `git add -A` widening fail the "commit contains exactly the spec"
   assertion; new test `create_spec_pr_refuses_changes_outside_specs_and_restores`
   covers the refusal path (branch removed, previous branch restored, change
   survives uncommitted).
2. **Major (gh-dependent test):** `create_spec_pr_with(root, name, gh_ok)`
   takes the readiness verdict as a parameter (wrapper `create_spec_pr`
   passes `gh_available()`); tests inject `gh_ok = true` so the git flow runs
   deterministically on any machine and only the final `gh pr create` step
   environment-dependently errors (named in the message either way).
3. **Minor (confirm not disarmed by post-confirm edits):** any input that
   actually changes the buffer text now disarms `confirm_discard` (content
   compared, not the dirty flag); regression test
   `editing_after_confirm_disarms_it`.
4. **Minor (confirm never rendered):** the editor title shows
   "— esc again to discard" when armed; the views test now asserts it.
5. **Nits:** "strictly read-only" wording corrected in README, the tui crate
   doc, and the crate description; save-now-broken reports a loud WARNING in
   the Ok status (spec text CMD-008-R1 updated to match); `visible_top` pure
   fn shared by editor state + renderer (`scroll_to_cursor` delegates);
   usize underflow on sub-2-column panes fixed; claim arithmetic corrected
   (base 168).
