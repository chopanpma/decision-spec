# Claim F31 — `decispec tui` phase 1: read-only spec cockpit

- **Task summary:** Add a ratatui TUI, launched as `decispec tui`, that
  connects the `.spec` files of registered projects (registry at
  `~/.config/decispec/registry.toml`, seeded with tvgo + verydian on first
  run) and offers three views per project: (1) formatted spec/decision browser
  (status levels: accepted/proposed/superseded/rejected), (2) generated
  artifacts rendered **in memory** via codegen's pure render fns — nothing is
  ever written into registered projects, (3) dashboard of decision-status
  counts, per-layer counts, and the last gate verdict from
  `.decispec/report.json`. `tui` crate = pure state + widgets (TestBackend
  TDD); `cli` owns crossterm, registry file I/O, workspace loading, and exit
  codes (0 clean quit, 2 setup failure, never 1). `--register <path>` adds a
  project. Design constraints pre-decided in `AGENT_TEAMS.md` §6/§12.
- **Agent:** main-orchestrator, 2026-10-20.
- **Files in scope (exact):**
  - `crates/tui/` (new crate: Cargo.toml, src/*.rs)
  - `crates/cli/src/main.rs` (CommandKind::Tui, registry I/O, event loop, load-project helper)
  - root: `Cargo.toml`, `Cargo.lock`, `README.md`, `docs/USAGE.md`,
    `ARCHITECTURE.md`
  - `.coord/BOARD.md` (F31 row only), this claim file
- **Must not touch:** `crates/{ir,parse,codegen,gate,store,extract,mcp}` (no
  API changes — gate's report types stay Serialize-only; the dashboard
  read-model lives in `tui`), `specs/`, `tests/glue/`, root docs not listed
  (`AGENTS.md`, `AGENT_TEAMS.md`, `decispec.toml`, `.gitignore`), other
  `.coord/` files, and the registered projects themselves (read-only; zero
  writes, zero adapter/toolchain runs).
- **Test plan (failing tests first, TDD):**
  1. `tui::registry` — parse/serialize round-trip of the registry TOML subset;
     malformed line → Err with line number.
  2. `tui::snapshot` — `GateSnapshot::parse` over a report.json-shaped
     fixture (verdict, counts, decision outcomes, kebab-case row results,
     ir `Layer`/`Status` reuse); unknown fields ignored; garbage → Err.
  3. `tui::app` — `update()` transitions: project selection clamp, mode
     cycling, entering Artifacts computes `render_all` + `render_index`
     in memory, 'r' → `Action::Reload`, 'q' → `Action::Quit`.
  4. `tui` views — ratatui `TestBackend` buffer assertions: project sidebar,
     decision detail (id, title, status, layers), artifact list + content,
     dashboard counts; a broken project shows its parse error instead of
     panicking.
  5. cli — registry write/read/seed with tempdir fixtures; `--register`
     resolves `[project].name` from the target's decispec.toml; broken
     workspace loads as error-state project, not a bail.

## Change summary

- **Added:** `crates/tui` (decispec-tui) — `registry` (hand-parsed TOML
  subset, round-trip, upsert, line-numbered errors), `snapshot`
  (`GateSnapshot` Deserialize read-model of `.decispec/report.json`,
  reusing ir `Layer`/`Status`, kebab-case `RowOutcome` mirror), `app`
  (`ProjectData`, `App`, `Input`/`Action`, pure `update`, in-memory
  `artifact_files` = `render_all` + `render_index`), `views` (sidebar /
  specs / artifacts / dashboard / status line, all `&App -> Buffer`).
  29 tests incl. TestBackend buffer assertions.
- **cli:** `decispec tui [--register <DIR>]` — registry path
  (`$XDG_CONFIG_HOME`/`~/.config/decispec/registry.toml`), first-run seeding
  of existing well-known projects (tvgo, verydian), `--register`
  (canonicalize + `[project].name` + upsert), per-project loading into
  error-state cards, crossterm event loop (draw → poll → translate → update),
  `r` reload, terminal restore on all paths. 7 new tests (register, seeding
  predicate, first-run persistence, broken-project load, gate report read,
  event translation, subcommand parse).
- **Exit-code surface:** `tui` exits 0 on clean quit, 2 on terminal/registry
  setup failure; never 1 (per AGENT_TEAMS.md §12 decision).
- **Root docs:** README (command table row, "The spec cockpit (TUI)"
