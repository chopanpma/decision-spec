# Claim F15 — `decispec extract` ingests ADRs into `decision` blocks

- **Owner:** main-orchestrator (execution delegated to coder agent-1)
- **Status:** claimed
- **Started:** 2026-10-01

## Task

Extend extraction so decisions already written as ADRs/markdown decision docs
become `decision` blocks in the draft spec, alongside the existing `model`
block. Deterministic only: title/status/context/consequences are extracted;
requirements and scenarios are NEVER inferred (that is the agent/human layer,
documented separately in docs/PORTING.md by the orchestrator).

## Scope

- crates: extract (analyze + render), cli (pass-through; cmd_extract output text)
- root: README.md (extract row), docs/USAGE.md (extract section),
  Cargo.lock (auto)
- OUT of scope: docs/PORTING.md (orchestrator), ARCHITECTURE.md (orchestrator),
  AGENTS.md, `.coord/*` except this claim

## Design (MVP)

- Scan for ADR files in `docs/adr/`, `docs/decisions/`, `adr/`, `decisions/`
  (case-insensitive), recursively; files matching `*.md`.
- Per file:
  - title = first `#` heading text (missing → skip file, count warning).
  - ID = `ADR-<number>` when filename has a numeric prefix (`0001-foo.md`,
    `0001.md`); else uppercase slug of the filename stem, charset-scrubbed,
    collision-suffixed (`_2`…). Never collide with a model container id —
    run the same `used` set.
  - status: match `## Status` heading's next non-empty line starting with
    proposed|accepted|deprecated|superseded|rejected (MADR), or an inline
    `Status: accepted` / `**Status:** accepted` line. Map deprecated→
    superseded; no match → `proposed` + warning count.
  - context = flattened single-line text under `## Context` (stop at next
    `## `); consequences = same for `## Consequences`. Flatten whitespace to
    spaces, cap at 500 chars with `…`. Multi-line strings are an MVP DSL
    limitation — flattening keeps the draft valid.
  - Do NOT extract `## Decision` body content; do not attempt `superseded_by`.
- `render_spec` emits decision blocks BEFORE the model block, each preceded by
  `# Source: <relative path>`. Draft must still round-trip through
  specforge_parse (extend the existing round-trip test to a fixture WITH ADRs).
- `Extracted` gains a `decisions: Vec<ExtractedDecision>`; `analyze` signature
  unchanged apart from internal scanning (keep `exclude` semantics — excluded
  dirs must not contribute ADRs either).

## Change summary

**Files changed:**
- `crates/extract/src/lib.rs` — new public `ExtractedDecision`
  (id/title/status/context/consequences/source); `Extracted` gains
  `decisions: Vec<ExtractedDecision>`; `analyze` scans ADRs after the import
  pass (signature unchanged; `exclude` semantics apply to ADR dirs via the
  same prefix check as `walk`); ADR helpers: `scan_adrs` (4 canonical
  locations `adr/`, `decisions/`, `docs/adr/`, `docs/decisions/`,
  case-insensitive, recursive, `*.md`), `adr_title` (first `#` heading;
  missing → skip + warning), `adr_id_base` (`ADR-<n>` numeric prefix, else
  uppercase charset-safe slug), `adr_status` (`## Status` section or inline
  `Status:`/`**Status:**`; deprecated→superseded; missing → proposed +
  warning), `adr_section` (`## Context`/`## Consequences` flattened to one
  line, ≤500 chars + `…`); decision ids share the container `used` set.
  `render_spec` emits decision blocks (each preceded by `# Source:`) before
  the `model` block; header line updated. 7 new tests.
- `crates/cli/src/main.rs` — `cmd_extract` progress line now says
  "review the draft (decisions from ADRs + structure from code), then add
  requirements"; 1 new test (`extract_writes_draft_with_decisions_from_adrs`,
  incl. `cmd_check` exit 0 on the written draft).
- `README.md` — extract row now documents ADR ingestion (locations, `# Source:`
  comments, requirements never inferred); crate-tree extract line extended.
- `docs/USAGE.md` — bootstrap section: extract command comment + paragraph
  updated for ADR ingestion.
- `Cargo.lock` — auto.

**Deviation from the brief — superseded decisions (needs reviewer ruling):**
the claim says "Map deprecated→superseded" and "do not attempt
superseded_by", but `decispec_parse::validate` rejects `status: superseded`
without a `superseded_by` target (and rejects unknown targets), so a literal
reading emits a draft that fails `decispec check`. Chosen resolution:
`ExtractedDecision.status` carries `superseded` as specified, and
`render_spec` emits `superseded_by: <own id>` (a self-reference) for
superseded decisions — the draft stays valid, deterministic, invents no
foreign ID, and the odd self-reference is exactly the kind of thing the
"review names" header asks a human to fix. Pinned by
`adr_status_from_heading_and_inline_line` (deprecated ADR round-trips
through parse+validate). If the reviewer prefers a different policy (e.g.
map deprecated→rejected, or emit a commented TODO instead), it's a 3-line
change in `render_spec` plus the one test.

**Design notes:**
- ADR-only projects (no source files) still fail with `NoSourceFiles` —
  `extract` remains a structure-first tool; ADRs ride along.
- Numeric ADR ids (`ADR-0001`) keep their dash; container ids are dash-free
  (sanitize), so the two families can only collide via single-word uppercase
  slugs — the collision machinery handles that via the shared `used` set.
- Warnings are summary lines, matching existing style: "N ADR file(s)
  skipped (no # title)", "N ADR(s) missing status (defaulted to proposed)".

## Review ruling (round 1)

The reviewer accepted the self-reference `superseded_by` policy as correct
(draft stays valid, no invented successor, gate treats superseded as
warnings-not-failures — fitting for a deprecated ADR), and required one
polish: mark the placeholder in-draft.

**Change:** when a decision renders `status: superseded`, the self-reference
`superseded_by:` line is now preceded by two TODO comment lines:

```
  # TODO: status was "superseded"/"deprecated" in the ADR; no successor determinable.
  # Point superseded_by at the real successor ID, then delete these comment lines.
  superseded_by: ADR-0001
```

Emitted only in the self-reference case (the sole superseded rendering
path); `#` comments parse anywhere, and the round-trip assertion proves the
draft still passes `decispec check`.

**Red evidence:** `adr_status_from_heading_and_inline_line` extended to
assert the TODO comment exists, appears exactly once, and precedes the
`superseded_by` line; against the un-polished renderer it failed with
`placeholder TODO comment missing` (right reason).
