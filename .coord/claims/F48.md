## Design notes

- cmd_init gains `root: &Path` (dispatch passes current_dir) — removes the
  cwd-global from tests, matches every other cmd_* seam.
- extract --to: conflict with --stdout checked before analyze (writes and
  prints nothing); target `<to>/<dirname(root)>.spec`; existing target →
  exit 2 untouched; create the store dir if absent; never writes into the
  analyzed repo's specs/ tree.
- init --from: each arg = a .spec file or a directory whose direct .spec
  children are taken (one level, per PORT-002 consequences). Nonexistent path
  or non-.spec file arg → exit 2 naming it. Duplicate target names (incl.
  collision with --demo's 0001-auth.spec) → exit 2. Existing specs/*.spec in
  the target → exit 2 untouched. Selected files are parsed+merged+validated
  as a workspace BEFORE any scaffold write; failures print file:line
  diagnostics and write nothing.
- Exit codes stay 0/1/2; no new crates or deps.

## Change summary

- `cli`: `cmd_extract(root, stdout, to)` — `--to <dir>` writes
  `<dir>/<dirname(root)>.spec` into the store, creating the store dir if
  absent; an existing target is exit 2 untouched (byte-identical); the
  analyzed repo's own specs/ tree is never written. `--to` + `--stdout` is
  rejected at the cmd seam before any analysis (writes and prints nothing)
  AND by a clap `conflicts_with` on the CLI surface.
- `cli`: `cmd_init(root, demo, from)` — new `root` param (dispatch passes
  current_dir), removing the process-cwd global from tests. `--from` args are
  .spec files and/or store directories (directories contribute their direct
  .spec children, one level, sorted). Check order: existing decispec.toml →
  exit 2; existing .spec files in target specs/ → exit 2 untouched (clobber
  refusal precedes any store read); selection errors (nonexistent / non-.spec
  arg) → exit 2 naming it; store parsed+merged+validated as one workspace
  BEFORE any write → file:line diagnostics on stderr, nothing written;
  duplicate target names (incl. collision with --demo's 0001-auth.spec) →
  exit 2. New helpers `select_store_specs` / `validate_store_specs` (unit-
  pinned by the broken-specs test, diagnostics asserted directly).
- Specs: PORT-001/PORT-002 → accepted, all 6 scenarios now carry
  `# delegates:` pins; header comment refreshed (spec-first red documented).
- Glue: +6 fns (all `decispec --bins`), docstring count 276 → 282.
- Docs: README init + extract command rows, new "Portable specs" section;
  docs/USAGE.md bootstrap section (extract --to / init --from prose).
- Exit-code contract unchanged (0/1/2); no new crates or deps.
