## Design notes for the implementer

- Computation lives in `gate` (pure): a rollup from the gate report /
  matrix to per-decision proof states + headline. `cli` owns the `coverage`
  subcommand + rendering and the gate summary line; `tui` renders marks and
  the dashboard aggregate from its existing report mirror (TUI-002).
- Proof states: `proven` (every gatable row passed) / `partial` (≥1 pass and
  ≥1 non-pass) / `unproven` (otherwise). SKIPPED is never proof. Headline =
  proven ÷ gatable (accepted+proposed) decisions, unweighted; superseded and
  rejected excluded. Exit codes per contract: 0 informational, 1 below
  `--min`, 2 with no report.
- Scenario count to pin: 14 (PROOF-001×3, PROOF-002×6, PROOF-003×2,
  PROOF-004×3, PROOF-005×1). Glue pins land in `tests/glue/__init__.py` at
  implementation.
