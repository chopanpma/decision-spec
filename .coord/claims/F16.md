# Claim F16 — `decispec mcp`: MCP server over stdio for agentic porting

- **Owner:** main-orchestrator (execution delegated to coder agent-1)
- **Status:** claimed
- **Started:** 2026-10-01

## Task

Expose DecisionSpec to AI agents as an MCP server (stdio transport,
newline-delimited JSON-RPC 2.0) so agents porting projects can call typed
tools instead of parsing CLI text. New pure crate `crates/mcp`; wired as a
`decispec mcp` subcommand in cli (one binary — agents configure
`{"command": "decispec", "args": ["mcp"]}`).

## Scope

- crates: mcp (NEW), cli (subcommand + dep only)
- root: Cargo.lock (auto), README.md (MCP section + config snippet),
  docs/USAGE.md (short section)
- OUT of scope: docs/PORTING.md (orchestrator adds the porting workflow
  section after), ARCHITECTURE.md (orchestrator), AGENTS.md, `.coord/*`

## Design

Protocol: MCP over stdio, one JSON object per line. Implement only:
`initialize` (result with protocolVersion `2025-03-26`, capabilities
`{tools: {}}`, serverInfo `{name: "decispec", version}`), `ping`,
`tools/list`, `tools/call`; ignore notifications (`initialized` etc.);
JSON-RPC error -32601 for unknown methods, -32700 for parse errors. No new
dependencies — serde/serde_json only (workspace deps).

Core is a pure, testable dispatcher: `handle_message(&mut Session, line:
&str) -> Option<String>` (None = notification, no reply). The stdio loop in
cli reads lines, feeds the dispatcher, writes replies. Session carries the
project root resolved at `initialize` time (cwd → walk up for
`decispec.toml`; tools accept an optional `path` arg to override).

Tools (all return JSON text; failures set `isError: true`):

1. `project_info` `{path?}` — root found, config (project name, lang,
   glue_module, fitness packages), file counts.
2. `extract_project` `{path?}` — `extract::analyze` JSON (lang, containers,
   relationships, decisions incl. source paths, warnings) + `render_spec`
   text + `render_fitness_toml` text.
3. `validate_spec` `{text, filename?}` — parse + validate ONE spec text
   (via specforge-parse) without touching the filesystem; diagnostics as
   structured JSON (file, line, message). THIS is the porting tool: agents
   iterate on proposed edits, get file:line errors back, then apply.
4. `check_workspace` `{path?}` — parse + validate all `specs/**/*.spec`,
   diagnostics JSON + counts (mirrors `decispec check` but structured).
5. `workspace_overview` `{path?}` — the porting work queue: decisions
   (id, title, status), per-decision requirements (id, layers, scenarios),
   gaps: accepted/proposed decisions with no requirements, requirements
   with no scenarios, superseded decisions still pointing at themselves
   (the F15 TODO placeholder).
6. `gate_status` `{path?}` — last `.decispec/report.json` if present:
   verdict, strict flag, counts, failing/uncovered/skipped row summaries;
   explicit `no report yet` result otherwise.

## Test plan (red first, all through the pure dispatcher)

1. `initialize` → correct protocolVersion/capabilities/serverInfo; a
   following `notifications/initialized` produces no output (None).
2. `tools/list` → exactly the 6 tools with inputSchema (required fields
   marked) and descriptions.
3. `validate_spec` with a broken spec → isError false, diagnostics JSON
   with file:line; with a valid spec → empty diagnostics; unknown method →
   -32601; malformed JSON line → -32700.
4. `extract_project` on a fixture (python pkgs + one MADR ADR) → decisions
   and containers present in JSON.
5. `workspace_overview` on a fixture with an accepted decision lacking
   requirements → gap listed; `check_workspace` on clean fixture → no
   diagnostics.
6. `gate_status` with no report → the explicit no-report result; with a
   hand-written report.json → verdict + counts parsed back.
7. cli: `cmd_mcp` exists, dispatches, and a piped-stdin test feeds two
   lines (initialize, tools/list) through the real binary's stdio if
   feasible in-process; otherwise test the loop function with a Cursor.

## Red evidence (2026-10-01)

Red-first per the 7-point plan. The crate skeleton (Session, handle_message
stub returning -32601 for every request, serve/serve_io loop) was written
first so failures are runtime assertions about the missing dispatcher/tools.

**`cargo test -p decispec-mcp` against the stub:**
`test result: FAILED. 0 passed; 7 failed` — every test failed on the stub's
`-32601 not implemented` (initialize payload, tools/list contents,
validate_spec diagnostics, extract_project JSON, workspace_overview gaps,
gate_status results, NDJSON loop).

**`cargo test -p decispec --bin decispec` (cli parse test):** failed to
compile pre-wiring (no `CommandKind::Mcp`), then green once wired — the
in-process stdio test was deliberately NOT attempted (cmd_mcp blocks on the
harness's stdin); the claim's plan allows the Cursor variant, which is
`serve_io_dispatches_ndjson_over_buffers` in the mcp crate.

**Test-authoring defect caught by the red run (fixture, not code):** the
overview fixture used `scenarios: []`, which the DSL lexer rejects ("expected
an identifier, found ']'"); `scenarios:` is optional and omitting it yields
an empty vec — fixture fixed to the legal form (verified via
`decispec check` on the same file).

## Change summary

**Files changed:**
- `crates/mcp/Cargo.toml` — NEW crate `decispec-mcp` (deps: decispec-parse,
  decispec-extract, serde, serde_json — no new external deps).
- `crates/mcp/src/lib.rs` — NEW: pure dispatcher `handle_message(&mut
  Session, &str) -> Option<String>` (initialize/ping/tools/list/tools/call,
  -32601 unknown method, -32700 parse error, notifications -> None);
  `Session { cwd, root }` (root resolved at initialize; per-call `path`

**Design decisions within the brief's latitude:**
- `gate_status` reads report.json as `serde_json::Value` and passes through
  verdict/strict/counts/failures/warnings plus fail/uncovered/skipped row
  summaries — `GateReport` is Serialize-only and mcp does not depend on the
  gate crate.
- `workspace_overview` returns diagnostics alongside the overview so agents
  see a broken workspace instead of a tool error.
- Tool-level failures (unknown tool, missing root, missing `text` arg) are
  `isError: true` results per MCP convention; only protocol-level issues
  are JSON-RPC errors.
