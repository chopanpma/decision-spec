# F41 — `decispec gen --only PREFIX[,PREFIX]`

## Task summary

User-queued console task (2026-10-20): regenerate a slice of the artifacts
without touching (or sweeping) the rest. `--only` selects specs whose id
starts with one of the given prefixes (same trim/comma style as gate's
`--prefix`, case-sensitive against spec ids like `CMD-009`).

## Agent

main-orchestrator (opencode)

## Scope

- `crates/codegen/src/lib.rs` — refactor `render_all` into
  `render_all_impl(ws, cfg, only)`; public `render_all` unchanged, new pure
  `render_all_for(ws, cfg, prefixes)` + tests
- `crates/cli/src/main.rs` — `Gen { --only }`, `cmd_gen(root, only)` +
  tests
- `specs/040-commands.spec` — decision CMD-010 + scenarios
- `tests/glue/__init__.py` — pins (+ docstring count)
- `README.md` — gen row only

Must not touch: gate/store/extract/tui crates, other specs, F39/F40 files.

## Design

- Under `--only`: only per-spec artifacts of matching specs (unit/contract/
  e2e/rust skeleton/infra rego) are rendered. Workspace-scoped outputs
  (model + flow diagrams, conftest.toml, fitness importlinter/depcruise)
  are skipped — they are whole-workspace views, not decision-owned.
- **The stale sweep is skipped entirely under `--only`** (partial render
  must never delete the rest); plain `gen` reconciles. The summary line
  says so.
- No spec matches any prefix → "no decision/spec matches --only X" +
  exit 1 (same finding class as query's no-match). Specs match but yield
  zero files → exit 0.
- `render_all(ws, cfg)` behavior byte-identical (render_all_for with an
  empty list == render_all).

  only: Option<&[String]>)`; public `render_all` byte-identical (pinned);
  new pure `render_all_for(ws, cfg, prefixes)` — filters per-spec artifacts
  by `spec.id.starts_with(prefix)`, skips workspace-scoped outputs (model
