# Review F8 — `specforge extract` — reviewer: main-orchestrator (author: coder agent-1)

Verdict: **APPROVE** (after two REQUEST-CHANGES rounds — see history)

## What shipped

New pure crate `specforge-extract` + `specforge extract [path] [--stdout]` in cli.
Draft `.spec` bootstrap from an existing Python/JS/TS project: containers from
top-level directories (or children of a single umbrella dir — `src/`, main
package), relationships from the import graph, suggested
`[stack.fitness.packages]` TOML. Scaffold-aware (glue dir + `tests/generated`
excluded), ID-scrubbed container names, round-trip acceptance test through the
real parser. 33 new/rewritten tests; workspace at **98 passed / 0 failed**,
clippy clean, verified independently by the reviewer (rebuilt, re-ran full
suite, and ran the binary against fresh Python/TS fixtures incl. pre-init
bootstrap, umbrella layout, and spaced dir names).

## Findings history

- **Round 1 (2 major, both fixed):**
  1. Container ids were raw dir names minus `-`→`_`, so `my pages/` emitted
     unparseable DSL (`container my pages ...`) — breaking the draft's
     `specforge check` promise. Fixed with an ASCII `[A-Za-z0-9_-]` scrub
     before the existing collision pass; titles keep raw names.
  2. `init` then `extract` (the documented quickstart) analyzed SpecForge's own
     glue scaffold — flipped small TS projects to "Python" via tie-break and
     produced a lone `tests` container. Fixed by passing glue-dir +
     `tests/generated` exclusions from cli into `analyze`.
- **Round 2 (1 major, 1 minor, both fixed):**
  3. Umbrella layouts (`src/{pages,lib}`, `shop/{auth,payments}`) collapsed to
     a single blob container with zero relationships — the most common real
     project shape, and it destroyed the import graph, the feature's main
     value. Fixed with single-umbrella promotion (exactly one depth-1 dir, ≥2
     child dirs with files; two+ depth-1 dirs never promote). Verified: the
     round-1 `shop/` e2e went from `container shop` + 7 unmapped imports to
     4 containers + 5 rels + 0 warnings.
  4. Python fitness suggestion emitted non-importable package names for
     hyphenated project dirs (`root_package = "my-shop"`). Fixed by scrubbing
     python dotted names only.

## Recommendations (forward-looking, non-blocking)

1. **Drift mode (post-MVP):** `specforge extract --check` — re-run `analyze`
   and compare against the committed draft, warning when the real import
   graph diverges. Cheap now that analysis is deterministic; closes the loop
   extraction opens.
2. **Unmapped-import noise:** the summary warning counts stdlib imports
   (`os`, `json`, `react`). A tiny per-language builtin list would make the
   warning signal real structure gaps only.
3. **F13 filed:** the parse lexer accepts Unicode alphanumerics in IDs while
   README documents ASCII `[A-Za-z0-9_-]+`. extract's scrubber already emits
   ASCII; tighten the lexer (`is_ascii_alphanumeric`) or amend the README so
   the grammar has one definition.
