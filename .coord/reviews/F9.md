# Review F9 — dependency-cruiser rule direction (+ unsafe regex)

- **Reviewer:** main-orchestrator (independent pass: suite, clippy, real tool)
- **Reviewed at:** commit-less working tree, 2026-10-02 (`.coord/claims/F9.md`)
- **Verdict:** **approve**

## What was asked

The rel `api -> auth` means *api may import auth*. The generated depcruise rule
forbade the opposite, and its path regexes made depcruise 18 refuse the file
outright. Fix direction-first, TDD.

## What was delivered

- `from` = the rel's TO side, `to` = the FROM side → "auth must not import api".
- Rule paths are `(^|/)id(/|\.|$)` (`depcruise_path_segment`), replacing
  `(^|[/\\])id([/\\]|$)`.
- Header NOTE documents the path-segment semantics.
- Tests assert the restricted side and the disallowed dependency, not the rule
  name or a regex shape — the exact reason the old test missed the inversion.

## Verification performed

1. `cargo build && cargo test` → 131 green (127 before), `cargo clippy
   --all-targets -- -D warnings` clean.
2. Red-first check: HEAD bodies + new tests → 6 failures (the four depcruise

   - landed config on the allowed tree → clean, `api-gateway/` and `api_v2/`

     the WIP);
   - landed config with `auth → api` → 1 violation, correct rule, exit 1.

## Findings raised and resolved during review

- **The WIP's bare-literal fix was not good enough.** `path: 'api'` is a
   substring match, so a sibling `api-gateway/` was reported as the `api`
   container — an allowed import would fail CI. Replaced with a segment-anchored
   pattern that depcruise 18 accepts (`(^|/)api(/|\.|$)`). The reviewer measured
   acceptance and matching against 18.5.0 before choosing it.
- **A false claim was about to ship.** The WIP header NOTE said "depcruise v18
   cruises 0 modules when handed directory args". Not reproducible on 18.5.0: a
   bare `src` directory arg cruised 3 modules (a directory with no sources gives
   0). The NOTE was rewritten rather than shipping an untrue instruction, and the
   board note is corrected in the F9 row.
- Test-scoping detail: the "no rejected constructs" check now collects the
  `from:`/`to:` path values instead of scanning the whole file (the header
   comment legitimately contains `*`).

## Remaining risk (accepted, documented)

- depcruise matches filesystem paths, so a container id must appear verbatim in
  the cruised tree. This is now stated in the generated header and in README.
- The CLI adapter still only cruises when `root/src` exists and passes `src` as
  the argument (pre-existing, documented MVP limitation — ARCHITECTURE.md item 4;
  `crates/cli` was not in F9's scope). Verified that a directory arg works on
  18.5.0, so this is not a blocker.
