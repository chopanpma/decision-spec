## Findings

- **minor** — `specs/020-codegen.spec:86-91` (`rust_skeletons_emitted_only_for_rust_stack`):
  then-clause says "rstest-style skeletons". Codegen emits plain `#[test]` +
  `todo!()` and the pinned test asserts exactly that; ARCHITECTURE.md:159-161
  already records README:183's "rstest-style" wording as a known doc bug. The
  spec propagated the stale doc word into a normative then-clause. One-word
  fix (drop the adjective) — recommended promptly, root cause lives in README.
- **minor** — `specs/050-mcp.spec:50` (MCP-002-R1): "WHEN an agent calls the
  workspace tools" overclaims — only 4 of the 6 tools have pinning scenarios;
  `project_info` and `check_workspace` are unpinned, and "the project overview"
  reads like `project_info`. Reword to name the four pinned tools; scenarios
  for the remaining two are a follow-up.
- **nit** — `specs/010-gate.spec:12` (GATE-001-R1): the closed "SHALL fail only
  when …" list enumerates 4 of README's 5 failure shapes — (d) executed-failing-test
  is pinned under ARCH-001 (`failing_junit_yields_fail`), so coverage exists,
  but the requirement text under-enumerates its own decision's (a)-(e)
  enumeration. Add the fifth clause for a faithful encoding.
- **nit** — `specs/010-gate.spec:50` (GATE-002 context): "six tests pin the
  boundary" — GATE-002 has 5 scenarios. Miscount (a sixth exists only if you
  count ARCH-004's non-strict baseline, which the sentence doesn't say).
- **nit** — `specs/010-gate.spec:12` drops README:194's "accepted/proposed"
  qualifier on "decision has no requirements" (scenario given-clauses do say
  "accepted"). Looser than the doc.
- **nit** — `specs/030-parse.spec` numbering starts at DSL-002; no DSL-001
  exists anywhere. Confirm intentional (e.g. reserved for F13's ID-charset
  ruling) or renumber.
- **ratified (spec beyond docs, judged acceptable)** — three behaviors are
  documented in spec + pinned by tests but absent from README/ARCHITECTURE:
  unclosed alt block = parse error (030:56), >30-containers grouping warning
  (040:217,244), and the GEN-004 mermaid charset rule (020:106-110). The specs
  are now the more precise record; recommend the orchestrator fold these into
  README rather than treat them as drift.

## Recommendations

- **Batch the glue by crate.** 131 serial `cargo test` subprocesses make the
  gate tier take minutes where ~8 invocations (one per crate/target, multiple
  `--exact` filters each) would do; correctness is unaffected, so this is a
  latency follow-up, not a defect. Alternatively document the cost in
  SPEC_AUTHORING's tier-1 section.
- Fold the three "spec beyond docs" behaviors into README (orchestrator queue),
  then fix README:183's "rstest-style" wording at the source so the next
  brownfield extraction doesn't re-propagate it.
- The author should record accept/decline + one-line reasons for each finding
  in `.coord/claims/F29.md` (per docs/REVIEW.md).
- No structural changes recommended, because the 1:1:1 pin registry (spec ↔
  glue ↔ Rust test) is exactly the ir::names discipline applied to dogfood, and
  the audit proves it holds across all 131 tests.
