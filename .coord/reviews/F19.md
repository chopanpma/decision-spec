# Review F19 — escape parens in Mermaid flowchart edge labels — reviewer: main-orchestrator (author: coder agent-1)

Verdict: **APPROVE**

## What shipped

User-reported bug, reproduced first by the reviewer (mermaid.ink bisection:
parens in an edge label → HTTP 400; without → 200; `&#40;`/`&#41;` entities
→ 200; node labels quoted and unaffected; PlantUML and sequence-diagram
message text unaffected). Fix: private `mermaid_edge_label()` applied only to
`mermaid_model` edge labels — `|` → `/`, `(` → `&#40;`, `)` → `&#41;` —
render-time only, IR keeps raw strings. 3 new tests; workspace **117 passed /
0 failed**, clippy clean.

## Independent verification

- Reviewer re-ran the suite: 117/0.
- Reviewer re-rendered the consumer's regenerated diagram via mermaid.ink:
  **HTTP 200** (was 400); edge line reads
  `-->|pages read state through lib &#40;api, application&#41;|` while the
  quoted node label right above keeps raw parens — exactly the intended split.
- Red evidence audited in claim: both failing tests failed for the right
  reason pre-fix (the exact 400 case, plus the pipe-terminates-label case
  caught preventively).

## Findings

None. The pipe substitution (`|` → `/`) went slightly beyond the reported
bug but is the same failure class (a raw `|` terminates the label early and
leaves dangling text) — justified preventive fix, pinned by test.

## Recommendations

1. Carried from earlier reviews: an `extract --check` / `gen --check` drift
   mode would catch render-level regressions like this in CI without a
   browser (render smoke tests need a mermaid validator — mermaid.ink is not
   CI-friendly; a node-based mermaid parse check is possible in tvgo's
   frontend toolchain if desired).
2. The DSL accepts any string in a rel label; other renderers may have their
   own forbidden sets. If more escape cases appear, centralize per-renderer
   label sanitizers rather than growing `mermaid_edge_label` ad hoc.
