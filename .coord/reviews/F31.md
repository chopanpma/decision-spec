## Findings

- **minor** — `crates/tui/src/snapshot.rs:171` (`parses_kebab_case_row_results`)
  does not actually pin kebab-case. The fixture's three row results
  ("pass", "uncovered", "skipped") deserialize identically under
  `rename_all = "snake_case"`, so the most plausible regression — someone
  changing the attr to snake_case — keeps the suite green while real
  report.json rows carrying `"no-artifacts"` then fail to deserialize
  (`result` → whole-report parse error → dashboard silently shows "no gate
  report"). Proven by mutation in the scratch copy (spot-check b). The mirror
  is correct today (verified against gate lib.rs:134); the gap is that the
  test named after the contract is blind to its only discriminating value.
  Fix: add a matrix row with `"result": "no-artifacts"` to `REPORT_JSON`.
- **minor** — Claim arithmetic/scope bookkeeping: the claim says "+7 decispec
  cli" tests; the diff actually adds **8** (`git show HEAD:… | grep -c '#\[test\]'`:
  25 → 33; 131 + 29 + 8 = 168). Also the BOARD.md diff flips the F28/F29 rows
  to `done`, outside F31's claimed "F31 row only" — benign orchestrator
  housekeeping for the Oct-7 reviews, but strictly a board-scope deviation.
- **nit** — `registry.rs:93` `strip_comment`'s doc promises comment stripping
  only *outside* double quotes, but no test covers `#` inside a quoted value
  (e.g. `name = "a#b"` — verified correct by reading; one fixture line would
  pin it).
- **nit** — `expand_home` (`main.rs:1601`, `~/` expansion for hand-edited
  registry paths) has no direct test.
- **nit** — `run_tui_loop` (main.rs:1656): if `EnterAlternateScreen` or
  `Terminal::new` fails, the `?` propagates before raw mode is disabled; the
  doc comment "restored on every exit path" overstates the setup-failure
  paths. Vanishingly rare; best-effort ordering would need a guard struct.
- **nit** — ARCHITECTURE.md's new T2 node label "registry =
  ~/.config/decispec" sits inside the pure `tui` box; the registry *file* is
  cli-owned (tui only parses the format). Reads as a location note, but blurs
  the boundary the diagram otherwise draws cleanly.

## Recommendations

- **Pin the kebab-case discriminating value before F32 builds on this
  mirror** (finding 1): one fixture row with `"result": "no-artifacts"` makes
  the snake_case mutation red. Cheap now, annoying to debug later against a
  real tvgo/verydian report.
- **Schedule a dogfood-pin follow-up** (new board row, not this one): F31 adds
  37 workspace tests that F29's 131-scenario registry does not pin; the gate
  matrix doesn't see them. Folding the TUI's commands/registry/snapshot
  behavior into this repo's own spec keeps the "tests are the spec" invariant
  the repo dogfoods.
- Consider a tiny `RestoreTerminal` guard (Drop → disable raw mode + leave
  alternate screen) so setup-failure paths get the same guarantee as the
  happy path; not required for this row.
- The author should record accept/decline + one-line reasons for each finding
  in `.coord/claims/F31.md` (per docs/REVIEW.md).
- No structural changes recommended, because the Input/Action split
  (pure `App::update` + cli-owned event pump) is the right seam: it made all
  three spot-check mutations possible to test without a terminal, which is
  exactly the testability the architecture claims to buy.
