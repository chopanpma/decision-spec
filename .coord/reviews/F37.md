## Findings

- **minor — claim evidence numbers are wrong in three places.** The claim
  says 14 scenarios (actual: 15 — 3+6+2+3+1); says "was 38/57/214 before
  this spec" (measured at F36 completion: 38 decisions / **52** requirements
  / **213** scenarios); and cites both "212 green" and "220 passed" as the
  unchanged suite. The deliverable itself is fine; the evidence block would
  mislead a later archaeologist. Author to correct in the restored claim.
- **minor — "gatable row" is the load-bearing undefined term.** PROOF-002
  builds the whole rollup on "every gatable row passed", but the spec never
  says which matrix rows count (invariants? infra policies? uncovered and
  no-artifacts rows — presumably "did not pass", but not stated). The
  implementer must pin this once, in code, beside the existing
  `DecisionOutcome`, and record the definition in the F38 claim.
- **nit — no scenario pins UNCOVERED / NO-ARTIFACTS rows' effect on proof
  state.** Derivable from R1's "at least one did not [pass]", but a cheap
  explicit scenario would stop an implementer from reading "uncovered ⇒
  unproven" instead of "uncovered ⇒ partial when other rows passed".
- **nit — corrupt or old-format `report.json` is unpinned.** Missing report
  exits 2; a present-but-unparseable one should too (same cannot-complete
  class). Recommend an F38 design note rather than a spec change.

## Recommendations

- The rollup must be **one pure function in `gate`**, reused by both
  `decispec coverage` and the gate summary line (PROOF-005-R1 demands they
  agree); the headline format string should live in one const, so the two
  surfaces cannot drift — the ARCH-003 registry pattern applied to console
  text. Building a second walk over the matrix for the gate line would be
  the exact failure PROOF-005's context warns about.
- The spec-first red is working as advertised: 15 loud AttributeErrors are
  a better backlog than a README list. No changes recommended to the
