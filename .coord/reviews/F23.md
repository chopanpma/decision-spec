# F23 review — edge labels: plain chars, no entities

Reviewer: main-orchestrator. Verdict: **approved** (board row → done).

## Root cause (user-reported on the tvgo draft PR, 2026-10-02)

GitHub's markdown pipeline HTML-decodes `&#40;`/`&#41;` BEFORE Mermaid parses
the fence. The entity that verified 200 on mermaid.ink arrived at GitHub's
Mermaid as a literal `(`, failing with "got 'PS'" (parenthesis token). The PR
error text showed the decoded parens — the decode-then-parse mechanism was
proven by the error itself. F19's verification method had this blind spot:
mermaid.ink receives the raw file bytes; GitHub decodes entities first.

## Fix (coder: agent-1)

`mermaid_edge_label` (codegen/src/lib.rs:158) no longer emits entities.
Parens are dropped, `|` → `/` kept, every char outside
`[A-Za-z0-9 ,./:-]` collapses to `-`. Out-of-charset collapse is the key
property: no entity, ampersand, or unicode punctuation can survive into an
edge label, so the decode attack is impossible rather than moved. Quoted node
labels keep raw text (parens are legal there; GitHub's own error was only on
the edge-label line).

## Lesson recorded

Cross-renderer mermaid safety requires PLAIN-CHARACTER labels. Any
HTML-entity workaround is unsafe on GitHub because of pre-parse entity
decoding. Future diagram features must keep this charset rule.
